# 真实连接案例：已替换识别信息

[English](case-study.md)

本案例观测于 2026 年 10 月。本文地址、账户标签、主机名、本地路径和密钥信息均采用示例表示，
保留报文关系与关键证据出现顺序。证据来自原始会话；发布包提供脱敏叙述，不包含原始凭据和未脱敏日志。

## 目标与环境

用户在 Windows 云工作站运行 Codex，希望它操作另一台 Linux 云工作站。
远端安装和登录 agent harness 不方便，但用户能打开可信 Linux 终端。
Windows 已有 PowerShell 7 和 OpenSSH，同时存在 TUN/代理程序。

示例拓扑：

```text
本机 Windows agent 10.23.7.10
    → 公网 SSH 映射 192.0.2.40:22022
    → Linux sshd 10.23.7.11:22
```

平台 SSH 已开启，界面显示允许所有来源 IP。会话中用户选定的登录账户为 root，
该选择属于本次任务的明确上下文。

## 建立登录凭据与主机身份

在本机生成专用 Ed25519 登录密钥，将私钥文件访问权限限制到创建它的 Windows 账户。
只将公钥提供给 Linux 控制台。第一次安装在普通账户下执行，写目标账户家目录时权限不足。
通过获准的 sudo 安装后成功，同时保留已有 authorized_keys 内容。

Linux 可信终端提供了服务器 Ed25519 主机公钥和 SHA256 指纹。
本机核对一致后存入独立 known-hosts 文件，使后续切换网络路径时继续验证同一设备身份。

## 改变判断的证据

| 观测 | 支持的结论 |
|---|---|
| 公网连接先显示 Connection established，随后在 SSH banner 前关闭 | 客户端可见连接未完成 SSH 协商 |
| Linux 监听 22，且本机 keyscan 有响应 | SSH 服务能够在本机完成协商 |
| 日志有启动记录，没有对应登录尝试 | 该日志中未看到认证阶段事件 |
| TUN 日志显示 DIRECT 上游连接超时 | 本地接受连接与上游连通是不同阶段 |
| 刷新平台 SSH 分配了新端口，故障仍然相同 | 此次入口刷新没有解决观测到的路径问题 |
| 同步抓包看到 SYN、SYN-ACK，缺少最终 ACK | 请求到达 Linux，但 TCP 握手未完成 |
| 内网 IP 使用固定主机密钥登录成功 | 可以通过该内网路径到达正确设备 |

关键抓包关系，数值已替换：

```text
入站：10.23.7.10:51000 → 10.23.7.11:22  SYN
出站：10.23.7.11:22 → 10.23.7.10:51000  SYN-ACK
入站：10.23.7.10:51000 → 10.23.7.11:22  SYN（重试）
出站：10.23.7.11:22 → 10.23.7.10:51000  SYN-ACK（重试）
```

抓包保留了本机工作站的内网来源地址。结合内网直连成功，现象符合公网映射回环或回程问题。
没有取得网关 NAT 配置或每一跳的双向抓包，因此未将某条 SNAT 规则缺失作为确定事实。

## 成功路径与后续复用

最终有效路径：

```text
Codex → 本机 PowerShell → SSH 10.23.7.11:22 → Linux 命令
```

主机密钥验证、密钥认证、主机名/账户检查和远端命令执行均成功。
可复用的 PowerShell 入口将内网作为已验证默认路径，将公网入口保存为独立选项。
之后设备重新启动时，通过内网路径再次连接成功。
其中一次新的 harness 会话使用沙箱账户，无法读取原有密钥/配置；通过宿主支持的权限流程复用了既有凭据。

## 可复用的经验

- 先确认用户有什么远端终端，以及终端当前账户，再安装公钥。
- 分别验证登录密钥、服务器身份、网络可达性和操作结果。
- TCP 表象矛盾时，检查实际路由和代理上游。
- 协调用户抓包与 agent 尝试的时间窗口。
- 条件合适时，用相同主机身份测试已确认的内网地址。
- 保存私有重连记录，设备重启后重新探测。

## 在其他环境中需要重新确认的事项

其他用户的本机与目标可能没有共享内网。
公网映射、跳板机、组网和主动出站反向隧道需要各自的路由与授权检查。
不同聊天入口未必提供本地工具。Root 权限、Windows 路径、云平台行为与后台常驻能力，
都应从当前环境验证，而不是从本案例直接套用。
